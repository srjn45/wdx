An agent runs an AI coding CLI in a terminal of its own: Claude Code, Codex, Cursor or Antigravity. wdx calls each an ACA, for AI coding agent. It drives every one the same way, so an agent's features are the same whichever runs it: its state read from the screen, messages delivered when it can take them, its model and permissions kept for every start, its conversation kept and resumed, and the same instructions to work through wdx.

## Choosing one

- **Installed and enabled.** An ACA is offered when its program is found through your login shell and its `aca.<id>.enabled` setting is true. `wdx agent acas` lists them, the default first; `wdx deps list` says which programs are found.
- **Per agent.** `wdx agent create --aca codex`, or the ACA field of TIDE's new agent form. Without it, the first offered, in the order Claude Code, Antigravity, Cursor, Codex.
- **Its model** is `--model`, as that CLI's own model flag takes it; `wdx agent models --aca <id>` lists what it offers. Without one, your own settings for that CLI decide.
- **Permissions.** `--permissions full`, the default, lets the agent work without asking, with network access and no sandbox; `ask` leaves that to your own settings for the CLI. Each page says what the two mean for its CLI.

## How wdx reads a screen

wdx keeps each agent's screen in the holder that runs it, and reads it as you would: the input box, the footer, the spinner of a running turn, the model's name. From that it tells working, idle and waiting apart, sees a draft you have typed, and knows when a message can go in. A screen it cannot read yet reads `unknown`. Nothing is asked of the AI CLI's vendor, and no API key passes through wdx: each CLI runs logged in as you are.
