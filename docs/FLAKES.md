# Flaky tests

Every test seen failing now and then, so that patterns show over time. AGENTS.md says how tests stay deterministic; this file says where they have not.

## Adding a row

Add a row when a flake is seen, in the same change as its fix if there is one. A failure nobody can explain yet gets a row too, with `open` as its fix: its repeats are what show the pattern. When a test flakes again, update its row rather than adding another, unless the cause is a different one.

Never answer a flake by retrying the test: half of those below were bugs in wdx.

- **Seen:** where it failed: CI, the nightly stress job, a local run, and whether the machine was loaded.
- **How often:** the failures and runs known, such as 3 of 24.
- **Pattern:** one from the list below, or a new one added to it.
- **Bug in wdx:** whether users could hit it, not only the test.
- **Fix:** the commit, or `open`.

## Patterns

- **Kill order:** a test kills processes in an order that lets another outcome come first. Kill so that only the wanted state can come. 2 flakes, none a bug in wdx.
- **Shared process:** parallel tests share a process's environment, working directory and open files, as with `text file busy` (golang.org/issue/22315). 1 flake.
- **Check too early:** a test reads, once, what another process writes only later. Wait for the state instead, keeping the check as strict. 12 flakes, not bugs in wdx.
- **Moment missed:** a test polls for something shown only for a moment, which a test scheduled late misses. Keep it up for as long as the test needs, through a field of `Timeouts`. 1 flake, not a bug in wdx.
- **Step raced:** a test acts during a step of another process that it does not hold, which a loaded machine lets end first. Hold the step open until the test has acted, or accept every state it can end in. 5 flakes, not bugs in wdx.
- **Too heavy for the batch size:** a batch of `make test-changed` runs out of its memory or its 20m, and fails whatever runs then. Make the package's batches smaller. 3 flakes, not bugs in wdx.
- **Too heavy for the memory cap:** `make test` runs four packages at once under a 3 GB cap, and the heaviest together pass it, so the kernel kills the run whatever its tests do. Make the heaviest packages lighter. 1 flake, not a bug in wdx.
- **Process left:** a program the test starts starts processes of its own that outlive it, which `runtest` finds at the run's end. Turn off what starts them in the test's environment. 1 flake, not a bug in wdx.
- **Map order:** a test reads what Go's maps leave in no set order, such as which of two equal entries a loop keeps. Compare only what the order cannot change. 1 flake, not a bug in wdx.
- **Product race:** the code itself races or gives up after a fixed time, and a loaded machine shows it. 20 flakes, all bugs in wdx or a library it uses but three, limits that only a machine far busier than a user's ran past. Suspect this first when a test fails only under load.
- **Disk full:** the tests' temporary files go in `/tmp`, a tmpfs shared with every other run on the machine, and a run fails wherever a write finds it full: `Disk quota exceeded`, or a log line cut off halfway. Not a bug in wdx: free `/tmp`. 1 flake.
- **No event:** a test waits for a state that only an event wdx does not watch for would bring, as an edit not staged, and passes only while some other read happens to come. Make the change in a way the watch sees. 1 flake, not a bug in wdx.
- **Half a write:** a test reads a file another process is writing, up to its end, and gets the last line cut where the writer had got to: a read can see part of a write. Read only whole lines, leaving the rest for the next read. 1 flake, not a bug in wdx.
